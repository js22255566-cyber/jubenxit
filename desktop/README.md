# 对白工坊 Windows 桌面版

Windows 10/11 x64。应用内包含工坊和 WhatsApp Web，可全屏切换或并排显示。工坊继续连接当前生产服务器，不打包服务器密钥或尚未上线的 AI 开发版。

## 安装和首次使用

运行 `Dialogue-Atelier-Setup-0.1.0.exe`，按向导选择安装位置，默认创建桌面和开始菜单快捷方式。当前构建没有商业代码签名证书；生产发布需另配证书，不要求用户关闭系统安全防护。

1. 工坊内登录原账号，沿用服务器上的 Google 和 AI 配置。
2. 点击 WhatsApp，用手机扫码连接；打开目标群，加载几条消息。
3. 点击顶部“绑定当前群”。
4. 回工坊 WS 设置，点击“检查连接”并启用联动。
5. 在测试群验证一条非客户消息，核对目标、两段格式和回执。结果未知时核对实际群聊，不自动重发。

不需要 Chrome 扩展。所有角色均通过实际登录的同一个 WhatsApp 账号发送，不模拟不同真实账号。桌面窗口可关闭后重新打开，登录会话与发送记录保存在本机当前 Windows 用户目录，卸载默认不清理用户数据。

**浏览器数据不会自动迁移：** Chrome 与 App 的登录、本地草稿及待同步记录独立。原浏览器里尚未保存到 Google 的消息，请保留原页面直到确认保存。不要因切换 App 清理浏览器数据。App 不会自动修复现有 Google 文档授权或保存异常。

如第三方账号登录服务限制内置窗口，须按服务允许的登录方式登录；本版尚需真实账号验证，不声称已完成真实 OAuth、扫码或发送验收。

## 开发与构建

在 `desktop` 目录执行：

```powershell
npm ci
npm test
npm start
npm run dist:win
```

安装包位于 `desktop/release`，无需 Node.js。GitHub Actions 的 `Windows desktop installer` 会在桌面代码更新后构建并保留安装包30天；可在该次运行的 Artifacts 中下载 `Dialogue-Atelier-Windows-x64`。

若标准 NSIS 编译器在受限环境中不能启动，可用 Windows 自带 .NET Framework x64 编译器构建离线安装版：先生成 `electron-builder --win dir --x64` 应用目录，再执行 `build-installer.ps1`。此安装版带安装向导、完整性校验、桌面与开始菜单快捷方式及 Windows“已安装的应用”卸载入口。卸载保留工坊用户数据，根目录中保留小型卸载器文件。安装器不下载或读取浏览器数据。

## 隔离与恢复

- 主进程 IPC 只接受本地壳窗口或指定生产工坊主框架；WhatsApp 回应只接受内置 WA 主框架。
- 远端页面启用 sandbox/contextIsolation，禁用 Node、webview 与通用文件/命令执行接口；不关闭 TLS 校验。
- 复用 `ws-extension` 的接收和发送回执逻辑，构建时生成沙箱 preload；没有浏览器扩展安装依赖。
- 发送账本用 Electron safeStorage/Windows保护；加密不可用或账本损坏时停止启动并保留原文件。
- 发起发送前先持久化稳定ID。未知任务不自动重发；迟到的确认回执可补回账本。
- App 和网页版都依赖网络及 Google/AI 服务，不宣称离线云端保存。

## 验证范围

Node 测试覆盖精确来源/框架权限、并发持久化与重启、损坏账本、不同消息ID但同人设/同正文连续发送、未知结果不重发、预加载脚本语法和接收注册。

`smoke.cjs` 为隐藏的纯本地 Electron 验证，既不打开工坊也不打开真实 WhatsApp。真实账号登录、Google读取/写入、扫码绑定、测试群发送和安装卸载是独立验收项；未完成时应如实注明。

回滚桌面版本不会回滚 Google 文档。可继续使用原网页版及扩展，保留 App 本地目录与未知结果记录，先核对实际群聊。
